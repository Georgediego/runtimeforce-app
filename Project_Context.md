# 📦 RUNTIMEFORCE — ЕДИНЫЙ КОНТЕКСТ ПРОЕКТА (MASTER FILE)

## 1. ОБЩАЯ ИДЕЯ ПРОДУКТА

**RuntimeForce** — это специализированная среда разработки и платформа оркестрации (AI Runtime Environment) для локальной и SSH-разработки. Продукт представляет собой легкий гибрид локального рантайма (Self-Hosted) и управляющего SaaS-слоя (Control Plane).

### Ключевая философия:

Пользователь взаимодействует с интерфейсом и логикой RuntimeForce, а не с конкретными LLM провайдерами. Модели являются лишь временными взаимозаменяемыми исполнителями текстовых и кодовых задач.

---

## 2. АРХИТЕКТУРНОЕ РАЗДЕЛЕНИЕ СИСТЕМЫ

Система жестко разделена на два изолированных слоя, взаимодействующих по единому унифицированному протоколу чата (**SSE JSON**). Любое дублирование кода исключено за счет выноса общей бизнес-логики в единый разделяемый слой ядра (Shared Core Layer).

### 🧠 runtimeforce-app (IDE Клиент)

Локальный легковесный монолит на базе **FastAPI**, разворачиваемый на локальной машине разработчика или на его приватном dev-VPS.

* **Интерфейс:** Monaco Editor, xterm.js терминал, распределенное дерево файлов, Git-визуализатор.
* **Управление рантаймами:** Асинхронное взаимодействие с локальной ОС (`asyncio.subprocess`) или удаленными серверами по SSH через пул асинхронных соединений.
* **Хранение данных:** Полностью контролирует приватные данные, контекст сессий и локальный кэш структуры файлов (SQLite).

## 4. КРИТИЧЕСКИЕ ПРАВИЛА БЕЗОПАСНОСТИ И ДАННЫХ (DATA SOVEREIGNTY)

### ❗ 1. Нулевое доверие к клиенту (Client NOT Trusted)

Вся логика проверки тарифов, лимитов токенов, Rate Limiting и проверки Pro-доступа выполняется **строго на стороне runtimeforce-server**. Локальный код не имеет административного влияния на биллинг-метрики.

### ❗ 2. Жесткое разделение конфиденциальности

* **Строго ЛОКАЛЬНО (`runtimeforce-app`):** SSH-доступы (пароли, приватные ключи), Git-токены (PAT персональные токены доступа), локальные пути и структура файлов проектов, а также **весь контекст и история диалогов**.
* **Строго на СЕРВЕРЕ (`runtimeforce-server`):** JWT-сессии, логика биллинга, usage-метрики (счетчики использования токенов для Pro).

### ❗ 3. Управление процессами терминала

Все терминальные PTY и SSH-сессии работают строго в асинхронных очередях (Async Queue). Бэкенд `runtimeforce-app` обязан принудительно выполнять cleanup при разрыве WebSocket-соединения с фронтендом, полностью исключая появление зомби-процессов.

### ❗ 4. Статус состояния (Stateless Backend)

Бэкенд-компоненты проектируются как stateless. Вся история и состояние рабочей сессии хранятся в контексте фронтенда и дублируются в локальную базу SQLite в качестве быстрого отказоустойчивого кэша.

# Финансовый контекст проекта: Биллинг и Налоги (RuntimeForce)

## 1. Провайдер биллинга и Юридический статус
* **Тип биллинга:** Merchant of Record (MoR) на базе платформы **Paddle Billing**.
* **Юридическое лицо:** ИП в Грузии (Статус малого бизнеса, налог 1% от валового оборота).
* **Схема налогообложения:** Экспорт IT-услуг (B2B-отношения с Paddle). Все налоги конечных пользователей (НДС, Sales Tax) администрируются на стороне Paddle. 
* **Правило декларирования:** В ежемесячный оборот ИП заносится вся сумма оплат пользователей (до вычета 5% комиссии Paddle) с конвертацией в лари (GEL) по курсу Нацбанка Грузии на день выплаты.

## 2. Тарифная сетка и Логика подписок
* **Free ($0 / мес):** Базовый тариф. Реализуется полностью на уровне внутренней БД проекта. Платежные шлюзы не вызываются.
* **Pro ($19 / мес):** Рекуррентная подписка через Paddle Checkout. Контроль лимитов AI и серверов.
* **Studio ($49 / мес):** Рекуррентная подписка через Paddle Checkout. Повышенные лимиты.
* **Enterprise ($99 / мес):** Рекуррентная подписка или оплата B2B-инвойсов через Paddle Invoicing.

## 3. Механика Триала (7 дней Pro без карты)
* **Тип интеграции:** Локальный (Бэкенд-ориентированный).
* **Логика работы:**
  1. При регистрации карта не запрашивается. В БД выставляется флаг триала на 7 дней.
  2. По истечении 7 дней бэкенд блокирует доступ к AI/SSH.
  3. В интерфейсе активируется кнопка оплаты, вызывающая оверлей Paddle Checkout (`Paddle.js`).
  4. После успешной оплаты подписка переводится в статус активной.

## 4. Контроль лимитов AI и Докупка (Сценарий А)
* **Принцип:** Предоплаченные пакеты (Add-ons) для защиты от перерасхода на стороне инфраструктуры.
* **Логика работы:**
  1. Каждый тариф имеет жесткий лимит встроенных токенов AI.
  2. При достижении лимита в 100% бэкенд блокирует вызовы к AI-моделям.
  3. Пользователю предлагается покупка фиксированного пакета (например, "+500k токенов за $5").
  4. Покупка обрабатывается через Paddle как одноразовый платеж (One-time charge).
  5. Начисление токенов происходит мгновенно по факту успешной транзакции без изменения расчетного периода основной подписки.

## 5. Интеграционные сущности Paddle API
* **Фронтенд:** Подключение библиотеки `Paddle.js` для генерации всплывающего окна оплаты (Overlay Checkout) по ID цены (`Price ID`).
* **Бэкенд (Обработка Вебхуков):** Сервер должен слушать и обрабатывать следующие ключевые события:
  * `subscription.activated` — успешное оформление подписки, открытие доступа к тарифу.
  * `subscription.past_due` — неудачная попытка списания (запуск Dunning-процесса, временная заморозка агентов).
  * `subscription.canceled` — отмена подписки, даунгрейд пользователя на тариф Free.
  * `transaction.completed` — успешная разовая оплата (для механики покупки доп. пакетов токенов).

## 20. ОРКЕСТРАТОР МОДЕЛЕЙ (КЛЮЧЕВАЯ ФУНКЦИЯ)

Главное отличие RuntimeForce от Cursor, Windsurf и большинства AI IDE:
RuntimeForce умеет работать не с одной моделью, а с группой моделей через единый оркестратор.

### Цель:

* Снизить стоимость
* Повысить надежность
* Исключить зависимость от одного провайдера
* Использовать бесплатные модели максимально эффективно

---

### ПРИНЦИП №1

Пользователь НЕ должен разбираться в моделях.
По умолчанию используется режим: **AUTO**.
Оркестратор сам принимает решения.

---

### ПРИНЦИП №2

Контекст принадлежит RuntimeForce, а не модели.
При переключении моделей:

* Контекст не теряется
* История не теряется
* Рабочее состояние не теряется

Модели являются временными исполнителями.
Контекст хранится в RuntimeForce.

---

### ПРИНЦИП №3

Бесплатный режим — полноценная функция продукта.
Это не урезанный режим.
Оркестратор обязан использовать бесплатные модели максимально эффективно.

---

### БЕСПЛАТНАЯ РОТАЦИЯ

Оркестратор отслеживает:

* Лимиты
* Ошибки
* Скорость ответа
* Качество ответов

При необходимости автоматически переключает модель.

#### Пример цепочки ротации:

Gemini → Groq → OpenRouter Free → Local Model (без потери контекста). Пользователь не должен замечать переключение.

---

### ДОСТУПНЫЕ РЕЖИМЫ

#### АВТО

Оркестратор сам принимает все решения. Рекомендуемый режим.

#### ПРОГРАММИРОВАНИЕ

Приоритет: код, рефакторинг, архитектура, генерация файлов.

#### АНАЛИТИКА

Приоритет: сложные рассуждения, исследования, длинный контекст, сравнения.

#### ЛОКАЛЬНЫЙ

Максимальный приоритет локальным моделям. Облако используется только при необходимости.

#### РУЧНОЙ

Пользователь выбирает конкретную модель. Оркестратор выполняет только fallback.

#### КОМБИНИРОВАННЫЙ

Пользователь может комбинировать несколько стратегий одновременно.

* *Пример:* Программирование + Аналитика + Local First.

#### КОНСИЛИУМ

Несколько моделей получают одну задачу.
Модели:

* Спорят
* Критикуют ответы друг друга
* Ищут ошибки
* Предлагают альтернативы

После этого оркестратор формирует итоговый ответ. Рекомендуется для архитектуры, аудита безопасности, сложных решений и выбора технологий.

---

### FALLBACK СИСТЕМА

При ошибке модели (timeout, rate limit, provider down, заведомо плохой ответ) оркестратор автоматически выбирает следующую модель. Происходит мгновенное переключение без потери контекста.

### SMART SCORING

Каждая модель на основе телеметрии получает динамический рейтинг по качеству, скорости, стоимости и стабильности. Оркестратор использует этот рейтинг для выбора оптимального исполнителя под текущий тип задачи.

Пользователь должен думать: **«Я общаюсь с RuntimeForce»**, а не «Я общаюсь с GPT, Claude или Gemini». Модель — деталь реализации, RuntimeForce — продукт.
